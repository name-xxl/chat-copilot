# Soul AI 聊天助手

Soul 网页版（home.soulapp.cn）开箱即用的油猴脚本，也给其它 DOM 结构规整的聊天站点留了自助接入的拾取向导，给聊天页加上无感 AI 能力：

- **先判断再回复**：先分析对方真实意图、风险 0–9、对方需要什么和回复策略，再按策略生成 3 条候选
- **回复建议**：输入栏上方显示判断结论和候选建议，点击即填入输入框（可修改后发送）；对方来新消息会自动刷新；`↻` 换一批
- **角色卡**：点击人物图标打开居中的角色卡，展示基础资料、性格侧写、事件记忆、话题偏好和对话攻略；打开只显示缓存，点 ↻ 手动提炼
- **主角档案**：在角色卡里切换到「我的主角卡」，填写身份、背景、稳定事实和说话风格；全局共享，生成时强制参考，减少编造和语气跳脱
- **AI 双卡提炼**：点「AI 提炼」，用一次请求同时更新对方卡和主角卡；主角信息只从你自己发出的消息推断，手填的姓名、边界和已有身份会保留
- **JSON 长期记忆**：每个会话单独保存记忆，只把已有记忆和新增消息交给模型合并；之后建议只读取记忆摘要和最近 12 条消息
- **导出**：对方角色卡和主角卡都支持导出 JSON 或 TXT
- **只辅助，不发送**：脚本不会点击发送按钮，也不会自动回复；发送与否始终由你决定
- **资料卡感知**：自动读取对方资料卡（匹配度、星球、认证、引力签、共同点）和双方昵称喂给 AI，回复贴合语境、站对视角
- **通用接口**：支持任意 OpenAI 兼容 API（DeepSeek / Kimi / 中转站 / 本地 Ollama 均可）

无侧栏、无悬浮球；输入区上方是一张内嵌卡片，会占据独立一行、不覆盖聊天消息，`×` 收起后留一个「✦ AI 建议」小胶囊。设置和角色卡使用居中悬浮弹窗。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展
2. Tampermonkey 面板 → 「添加新脚本」→ 清空后把 `soul-ai-chat.user.js` 全部内容粘贴进去 → 保存（Ctrl+S）
3. 打开 https://home.soulapp.cn/chat 并登录 Soul 账号（其它网站先看下方「接入新平台（拾取向导）」）
4. 点开一个会话，输入栏上方会出现建议条（未配置 API 时显示提示）

## 配置

点建议条上的 `⚙` 弹出设置：

| 配置 | 说明 |
| --- | --- |
| Base URL | OpenAI 兼容接口地址，如 `https://api.deepseek.com`、`https://api.moonshot.cn`；也可以直接填写完整的 `/v1/chat/completions` 地址 |
| API Key | 对应平台的 Key（只存在油猴脚本存储里，请求直连你配置的域名） |
| 模型名 | 如 `deepseek-chat`、`kimi-k2-0711-preview` |
| 我的昵称 | 与主角卡姓名同步；AI 会把聊天记录整理成带名字的文字稿，以这个身份替你说话 |
| 人设 Prompt | AI 的性格底色（system 提示词）；具体的身份、事实和说话风格建议写进主角卡，冲突时以主角卡为准 |
| 温度 | 0~1，越高越放飞；非法输入不会被保存 |
| 思考模式 | `自动`（默认，不传参数）/ `开启` / `关闭`；仅部分模型（如 LongCat）支持显式控制，其他接口保持「自动」即可，避免未知参数报错 |
| 主题 | `跟随页面`（默认：自动检测宿主明暗 + 提取发送按钮/采样点主色，含子元素；拾取接入的站点暗色底板还会跟随页面表面色，避免出现不搭的色块）/ `浅色` / `深色` |
| 自定义主色 | `#RRGGBB`，留空跟随页面；填写后覆盖自动提取 |
| 先判断意图和风险 | 默认开启。每次新消息先用独立请求判断意图/风险，再生成建议；关闭后恢复单次请求 |

还没有长期记忆时，脚本最多读取最近 30 条非系统消息；生成记忆后，请求只带“记忆摘要 + 最近 12 条消息”，不会重复喂整段历史。记忆按会话保存在油猴存储中，内容为 JSON，包含关系概览、话题、稳定事实和未完成约定。

主角档案独立于会话，作为全局 JSON 共享。生成回复时会把“身份、背景、稳定事实、性格、说话风格、常用表达、禁区”加入 system 提示，并明确要求：档案里没有的个人事实不要编造，说话风格优先遵循主角档案。

角色卡的「AI 提炼」只用一次请求同时更新两张卡：主角卡只分析用户自己发出的消息，推断身份、背景、兴趣、常用表达和语言风格；姓名、边界以及已经手填的身份/背景/风格不会被覆盖，标签、兴趣、常用表达和事实采用合并去重。对方卡则重新提炼关系阶段、性格、事件和攻略。

生成建议时，每条新消息通常会产生两次接口调用；同一会话点 `↻` 会复用已有判断。角色卡不会自动请求，只在手动点「重新分析」或「AI 提炼」时才调用接口。长期记忆使用独立请求做增量总结：累计 4 条以上新消息且聊天静默约 15 秒后整理；积攒到 8 条时缩短到约 3 秒；打开或手动刷新角色卡也会触发整理。没有真正的话题结束信号，因此用“静默时间 + 新增条数”近似。会话识别采用三层机制：优先在你点开会话的瞬间抓取该条目身份，其次读取聊天窗固定头部（`.detail-header`）与资料卡，最后按“消息锚点仍在消息流中”沿用当前身份——资料卡因消息过多被滚出视图、或消息列表虚拟化导致首条消息不可见时，功能不受影响。

## 使用

- **判断结论**：建议上方显示风险分、真实意图、是否给实质和建议策略；高风险时三条候选会优先接情绪、避免讲道理
- **建议**：打开会话自动生成；点卡片会替换并填入输入框，改完自己按发送；`↻` 换一批；`×` 收起（留 ✦ 可再展开）；全新会话还没有消息时直接给打招呼的第一句话（不做意图判断），对方回复后恢复正常判断
- **角色卡**：点人物图标打开居中角色卡；基础资料与已有缓存立即显示，不再自动请求接口；点右上角 ↻ 手动提炼/重新分析
- **主角卡**：在角色卡顶部切换到「我的主角卡」，填写身份、稳定事实和说话风格后保存，所有会话共享
- **AI 提炼双卡**：点卡片顶部的「AI 提炼」，一次请求同时刷新对方卡和主角卡；主角信息来自你自己发出的消息，手填字段优先
- **导出**：两张卡都有「导出 JSON」「导出 TXT」按钮，导出当前内容用于备份或迁移
- **记忆更新**：聊天告一段落后自动把新增内容合并进 JSON 记忆，角色卡的“长期记忆”和“事件记忆”会同步更新；发现记忆里混入了别的会话的内容时，点角色卡长期记忆区的「清除本会话记忆」，再手动重新提炼即可按当前聊天重建
- **消息刷新**：对方发来新消息后会自动重新判断并刷新建议
- **发送权**：脚本只填入输入框，从不自动点击发送

## 接入新平台（拾取向导）

v1.9.0 起，除了内置适配的 Soul 域名，其它 DOM 结构规整的聊天网站可以通过拾取向导自助接入，全程点选、无需写代码。已适配的 Soul 域名开箱即用；canvas 渲染或跨域 iframe 内的聊天窗不支持。

在目标站点点 Tampermonkey 图标 → 「启动拾取向导（教我识别当前站点）」，按面板引导依次点选页面元素，共七步：

1. **消息流容器** ×1：整个聊天消息列表
2. **对方消息** ×2：点两条对方发来的消息作样例
3. **自己消息** ×2：点两条你发出的消息，用于和对方消息做差分区分角色；无法区分时所有消息都会视为对方消息（角色识别与角色卡降级）
4. **输入框** ×1：可编辑的输入区域；发送按钮会沿输入框父链自动推导
5. **身份来源**三选一：侧栏条目（点当前激活的会话项，再点选其余条目辅助差分，最可靠）/ 聊天头 / URL（路径即身份）
6. **资料卡**（可选）：对方的资料卡弹层，可「跳过此步」
7. **主色采样点**（可选）：取哪个元素的主题色，可「跳过此步」

拾取完成后自动生成自检报告：消息条数（对方/自己）、输入框类型与写入方式（富文本/原生控件）、身份可靠级，并发起一次真实的建议生成做端到端确认（API 未配置时仅结构自检，仍可保存，之后在设置里配好 AI 即可）。点「保存并启用」后页面自动刷新生效；配置按域名单独保存，各站点互不影响。

**页面结构改版后**：建议条会提示「页面结构已变化，部分功能暂时失效」，点旁边的「重新定位（约 30 秒）」重开向导再拾取一遍（旧配置在保存新配置前持续生效）。想放弃某站的自定义配置时，用 Tampermonkey 菜单的「清除本站拾取配置（恢复内置/停用）」：Soul 域名恢复内置适配器，其它站点停用脚本。

## 安全与隐私

聊天记录、双方昵称、对方资料卡和主角档案中填写的内容会发送到你配置的 OpenAI 兼容接口；开启判断后会先发送一次分析请求，再发送一次建议生成请求；打开角色卡还会发送一次角色卡分析请求；「AI 提炼双卡」会发送一次联合分析请求；长期记忆会单独发送“已有记忆 + 新增消息”做增量总结。JSON 记忆、主角档案和 API Key 都保存在油猴存储中，请确认接口域名可信。脚本不会自动发送消息，但请求内容仍会经过你配置的 API 服务商，敏感对话请谨慎使用。导出的 JSON/TXT 包含个人信息，请妥善保管。

## 文件

- `soul-ai-chat.user.js` — 构建产物（单文件，安装时粘贴这个）
- `AGENTS.md` — 项目约定：架构分层、归一强约束、五维度质量标准、领域红线与开发流程
- `ROADMAP.md` — 升级计划：主题适配 → 平台适配器 → 拾取向导 → 多平台 2.0 的分阶段路线
- `src/` — 源码（ES Module，按职责分层）：
  - `selectors.js` / `config.js` / `storage.js` — Soul 适配器选择器（页面改版改这里）、配置与 GM 存储封装（存储键统一注册在 storage.js）
  - `platform.js` + `platform/`（`soul` 内置适配器 / `custom` 拾取配置驱动适配器 / `null` 空适配器）— 平台门面（稳定采集/定位接口、输入写入、滚动保持、选择器健康检查、拾取配置读写与适配器选择）
  - `selector-gen.js` / `role-diff.js` / `platform-config.js` — 选择器泛化、角色差分、拾取配置校验（纯函数）
  - `constants.js` / `request-guard.js` / `utils.js` / `state.js` / `actions.js` — 跨模块常量、请求守卫（防竞态+可中止）、纯工具、全局可变状态中心、UI↔流程动作总线
  - `dom.js` / `transcript.js` — Soul 页面采集与文字稿（dom.js 另含通用的元素序列化与选择器计数）
  - `ai-client.js` / `prompts.js` / `suggestions.js` / `insight.js` / `character.js` / `profile.js` / `memory.js` — 接口客户端、提示词组装与各数据域的校验
  - `ui.js` + `ui/`（`shared`/`style`/`template`/`bar`/`modals`/`settings`/`card`/`core`/`theme`/`wizard`，门面统一导出） / `suggestion-flow.js` / `cards-flow.js` / `memory-flow.js` / `wizard-flow.js`（拾取向导流程） / `chat-monitor.js` — Shadow DOM UI 与各业务流程
- `ui-preview.html` — UI 设计稿（本地起 http 服务即可预览）

## 开发

```bash
npm install     # 安装 esbuild
npm test        # 纯函数单元测试（node --test，零依赖）
npm run build   # src/ → soul-ai-chat.user.js（单文件油猴脚本）
```

版本号唯一来源是 `package.json`：构建时自动注入 userscript 头部 `@version` 与运行时启动日志。

页面选择器集中在 `src/selectors.js`，Soul 页面改版导致功能失效时改这里即可；其它站点用拾取向导重拾取一遍。改完重新构建。
